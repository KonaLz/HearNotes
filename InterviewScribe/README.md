# Meeting Scribe 项目说明

## 1. 项目用途

Meeting Scribe 是一款运行在 Windows 本机上的录音转写工具。它可以导入 MP3、M4A、WAV、FLAC 等录音，使用本地语音模型完成文字转写，并根据声音把内容分成 A、B、C 等发言人。转写结果可以逐段回听、修改文字、修改发言人，也可以一次性修改每位发言人的名字并同步到整篇记录和导出文件。

所有录音、转写文字和模型推理都在本机完成，正常转写过程不需要 API Key，也不会把录音上传到外部服务。

## 2. 使用方法

1. 双击 `启动听记.vbs`。
2. 程序会启动一个仅监听本机地址的网页界面，并自动打开浏览器。
3. 在“界面语言”中选择中文、日本語或 English。首次打开时会根据操作系统语言选择；手动选择后会保存在浏览器本地设置中。
4. 选择录音文件。录音语言和发言人数默认都是“自动”。如果已知语言或人数，可以手动指定以提高稳定性。
5. 点击“开始转写并区分发言人”。处理期间可以查看进度，完成后进入编辑器。
6. 在上方给 A、B、C 输入名字。名字只需要输入一次，保存后会更新所有相关段落和导出内容。
7. 点击时间按钮回听原声，修正文字、发言人归属或“待核”标记。
8. 选择 TXT、Markdown、SRT 或 JSON 后导出。

在左侧“最近的录音”列表中，点击某条记录右侧的“删除”按钮，可以删除该录音及其转写结果。删除前会要求确认，删除后无法恢复；正在处理中的任务需要先取消。

## 3. 代码结构

| 文件 | 作用 |
| --- | --- |
| `启动听记.vbs` | Windows 入口，寻找项目使用的 Python 运行时并启动 `launch.py`。 |
| `launch.py` | 无窗口启动入口，记录启动异常并调用本地 HTTP 服务。 |
| `bootstrap.py` | 配置本地 Python 组件、CUDA DLL 路径和离线环境变量，并检查模型是否齐全。 |
| `server.py` | 本地网页服务器、Cookie 校验、上传、任务生命周期、取消、保存、导出和模型更新接口。 |
| `worker.py` | 单条录音的实际处理流程：解码、说话人分离、Whisper 转写、时间对齐和结果保存。 |
| `core.py` | 词级时间戳与说话人时间段的对齐、A/B/C 映射、编辑校验和导出格式生成。 |
| `models.py` | 查询、下载、校验、启用和回滚模型版本。新模型写入独立目录，不覆盖旧模型。 |
| `prepare_models.py` | 准备或检查本地模型文件。 |
| `ui/index.html` | 页面结构和初始后备文字。 |
| `ui/app.js` | 页面交互、上传进度、任务轮询、编辑器和导出操作。 |
| `ui/i18n.js` | **所有界面文案和中文/日语/英文翻译的集中维护文件。** 修改显示文字时优先编辑此文件。 |
| `ui/style.css` | 页面布局和视觉样式。 |

## 4. 一次转写的内部流程

```text
选择录音
  ↓
浏览器上传到 data/jobs/<任务编号>/
  ↓
worker.py 解码为 16 kHz 单声道音频
  ↓
sherpa-onnx 生成说话人时间段 ─┐
                               ├→ 等待两项完成
faster-whisper 生成词级时间戳 ─┘
  ↓
core.py 按时间重叠把词分配给说话人
  ↓
合并相邻短词，标记低置信度或重叠边界
  ↓
保存 result.json，网页进入可编辑状态
```

说话人编号是根据声音首次出现的顺序映射为 A、B、C。它代表“声音分组”，不是身份认证；重叠发言、很短的应答、噪音或距离麦克风较远时，仍可能需要人工回听确认。

“智能加速”会让 Whisper 使用 GPU、说话人分离使用 CPU，并行处理后再对齐；这是本机实测最快的默认组合。“全部使用 GPU”可用于对照测试，但两个模型同时争用显卡时不一定更快。精度档位分别调整说话人窗口重叠量和 Whisper 搜索范围：均衡适合日常面试，精确更慢，快速更容易需要人工校对。

## 5. 翻译文案如何维护

请编辑 [`ui/i18n.js`](ui/i18n.js)：

- `zh`：中文
- `ja`：日语
- `en`：英文

三种语言使用相同的键名。新增文案时，应同时在三组中增加同名键，避免某种语言切换后回退到中文。带 `{n}` 的文字可以通过 `trf()` 插入数字，例如人数选项。

页面运行时由 `app.js` 调用 `tr("key")` 读取文案。`index.html` 中保留少量中文后备文字，用于脚本尚未执行时的首屏显示；脚本加载后会以 `i18n.js` 的内容覆盖。

## 6. 模型和更新

语音转写模型使用本地 faster-whisper，声音分组使用 sherpa-onnx 和 3D-Speaker。模型页的更新流程是：

1. 查询官方版本和文件摘要；
2. 用户明确点击下载后写入新的版本目录；
3. 校验下载长度、SHA-256 和模型能否加载；
4. 校验成功后才切换 `data/models.json` 中的活动版本；
5. 旧版本保留，可从模型页回滚。

更新失败时继续使用原模型，不会删除已经可用的模型。模型格式发生较大变化时，可能需要先更新程序代码。

## 7. 数据目录

- `data/instance.json`：当前本地服务地址、随机访问密钥和进程编号。
- `data/jobs/`：每条录音的原文件、播放 WAV、进度、日志和转写结果。
- `data/models.json`：活动模型和上一版本模型的路径。
- `models/`：当前说话人模型及其版本目录。

这些文件可能包含录音和面试内容，备份或迁移时应整体保护 `data/` 目录。

## 8. 常见问题

### 页面提示“请双击软件目录中的启动文件”

请从项目目录双击 `启动听记.vbs`，不要直接用浏览器打开普通文件路径。服务会通过随机 Cookie 限制本机页面访问。

### GPU 不可用

程序会先尝试 CUDA；如果 CUDA DLL、显存或首次推理失败，会自动切换 CPU。CPU 模式速度较慢，但结果仍会保存。

### 发言人分错

在编辑器中直接修改对应段落左侧的发言人下拉框，然后保存。上方的全局名字输入框只负责把 A、B、C 改成实际称呼。

### 模型更新失败

查看模型页的错误信息和 `data` 目录日志。更新采用原子切换，失败时旧模型仍可继续使用。

## 9. 开发前检查

修改 Python 后可以用项目自带 Python 运行时执行：

```powershell
$rt = "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
& $rt -m py_compile InterviewScribe\server.py InterviewScribe\worker.py InterviewScribe\core.py InterviewScribe\models.py
```

修改前端后检查：

```powershell
node --check InterviewScribe\ui\app.js
node --check InterviewScribe\ui\i18n.js
```

涉及页面文案时，建议在中文、日语、英文之间各切换一次，并确认录音语言和发言人数仍然默认显示为“自动”。
